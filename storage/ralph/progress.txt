## Codebase Patterns

- **Feature status é computado**: FeatureStatus no model Feature é um accessor (não persistido). Draft = sem tasks, Done = todas tasks done, Doing = alguma task doing, etc.
- **Feature kanban padrão visual**: Cards com título, progress bar, badges (prioridade, tempo, due date), timer controls, tasks expandíveis. Mesmo padrão da página Work (⚡features.blade.php).
- **getColumnFeatures pattern**: Filtrar features por computed status usando `->filter(fn (Feature $f) => $f->status === $status)->take($limit)`. Não usar query builder (status não é coluna).
- **Testes de feature kanban**: Criar features com tasks específicas para forçar status desejado. Ex: feature sem tasks = Draft, feature com task backlog = Backlog.
- **SFC project-detail**: Arquivo grande (~1000 linhas). PHP class + Blade template. Tabs: Board, Docs, Métricas.
