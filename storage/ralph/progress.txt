## Codebase Patterns

- **Flux badges pattern**: `<flux:badge size="sm" color="violet" icon="cpu-chip">Contexto</flux:badge>` — seguir padrão de badges existentes (is_pinned usa amber/star)
- **Checkbox com descrição**: `<flux:checkbox wire:model="prop" label="Label" description="Descrição" />` — Flux suporta `description` diretamente
- **Document edit save pattern**: Dados salvos via array `$data` no método `save()` — adicionar campos novos ao array
- **Document edit mount pattern**: Propriedades carregadas no `mount()` do SFC a partir do model
- **Project-detail docs tab**: 4 locais para badges/IDs de documento: desktop list, desktop preview header, mobile list, mobile preview modal header
- **Copy-to-clipboard pattern (Alpine.js)**: `x-data="{ copied: false }" x-on:click="navigator.clipboard.writeText('...'); copied = true; setTimeout(() => copied = false, 1500)"` com `:class="copied ? 'text-emerald-400' : 'text-zinc-500 hover:text-zinc-300'"` — usado em feature-modal, feature-card, e agora document-view/edit
- **MCP Tool testing pattern**: `SoloBoardServer::tool(ToolClass::class, ['param' => 'value'])` → `$response->assertOk()`, `assertSee()`, `assertDontSee()`, `assertHasErrors()`
- **Factory default gotcha**: `DocumentFactory` não define `is_context` no default — atributo fica `null` até refresh do DB (que aplica o default `false`)
- **Testes pré-existentes falhando**: AiInsightsTest (5), AiIntegrationTest (1), AnalyticsPageTest (3), DocumentIntegrationTest (1 - task modal) — NÃO são causados pelas mudanças de documentos
