## Codebase Patterns

- **Kanban filters**: Cada filtro é uma property com `#[Url]`, aplicada em `buildColumnQuery()` com AND logic. Template usa `<flux:select>` e `<flux:button>` na barra de filtros (linhas ~226-256).
- **Livewire test pattern**: `beforeEach` com `$this->actingAs(User::factory()->create())`, `Livewire::test('pages::nome')`, `set()` para filtros, `assertSee/assertDontSee` para verificar conteúdo. Para verificar ordem, usar `assertSeeInOrder()` — NÃO usar `viewData('__instance')` que não funciona no Livewire 4.
- **Flux sortable columns**: `<flux:table.column sortable :sorted="$sortBy === 'col'" :direction="$sortDirection" wire:click="sort('col')">Label</flux:table.column>`
- **Task factory states**: `->todo()`, `->backlog()`, `->doing()`, `->done()`, `->overdue()`, `->urgent()`, `->withDueDate()`, `->withEstimate()`.
- **Database**: PostgreSQL — usar `ilike` para case-insensitive search, não `like`.
- **Features computed status**: Feature.status é um Attribute computado (não coluna DB). Para filtrar por status, aplicar `->filter()` após `->get()`, não no query builder.
